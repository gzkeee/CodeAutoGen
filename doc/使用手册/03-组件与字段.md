# 03 · 组件与字段

本章详解四种组件的能力与使用方式：**Form、Table、Modal、Container**，以及字段类型。

---

## 1. Form（表单）

用于**查询**、**新增**、**编辑**等交互场景。根据 `url` 的配置自动生成不同行为：

| url 配置 | 生成行为 |
|----------|---------|
| 只有 `query` | 查询表单：带「查询 / 重置」按钮，提交后把结果传给下游 |
| 只有 `save` | 保存表单：带「保存」按钮，提交后提示「保存成功」 |
| `load` + `save` | 打开时加载回显 + 保存 |

```json
{
  "SearchForm": {
    "Type": "Form",
    "Fields": [
      { "name": "USER_NAME", "type": "Input", "label": "用户名" }
    ],
    "url": { "query": "/api/user/list" }
  }
}
```

生成的组件特征：

- 布局 `inline`（一行排列）
- 字段元信息集中在 **`formItems` 配置常量**里，控件 JSX 通过 `{...formItems.KEY}` 展开（维护指南见 [07](07-生成代码与常见问题.md)）
- 查询提交 → `props.setValue(数据)` 交给父级 / 下游组件
- `DatePicker` 字段回显时自动做 dayjs 转换

---

## 2. Table（表格）

用于**数据展示**与**行点击传递**。配合不同 `url` 和上游关系有四种数据来源：

| 场景 | 数据来源 |
|------|---------|
| 配了 `url.load`，无上游行数据 | 挂载时 `load` 加载 |
| 上游是 Form（查询） | 直接接收表单查询结果（`value` prop） |
| 配了 `url.load`，上游是 Table（主从） | 收到行数据时，用 `load` 重新加载明细 |
| 无 `url`、无上游 | 空表（只渲染列头） |

```json
{
  "UserTable": {
    "Type": "Table",
    "Fields": [
      { "name": "USER_NAME", "label": "用户名" },
      { "name": "STATUS", "label": "状态" }
    ],
    "url": { "load": "/api/user/page" }
  }
}
```

生成的组件特征：

- 行唯一标识基于 **WeakMap 生成器**（相同记录返回相同 ID，避免重渲染问题）
- `onRow` 行点击会按数据流配置触发下游（编辑弹窗回显、明细表加载、输出到父级）

## 3. Modal（弹窗）

通过 `Layout: "Modal"` 让任何 Form / Table 变成弹窗：

```json
{
  "AddUserModal": {
    "Type": "Form",
    "Layout": "Modal",
    "Fields": [ /* ... */ ],
    "url": { "save": "/api/user/add" }
  }
}
```

### 3.1 四种角色（自动推导，无需配置）

工具根据弹窗的**入度 / 出度**自动判定角色：

| 角色 | 判定逻辑 | 行为 |
|------|---------|------|
| `source` | 有出度、无入度 | 由「按钮」触发打开 |
| `target` | 有入度、无出度 | 收到数据时**自动打开**（如点表格行 → 编辑弹窗弹出） |
| `both` | 有入度 + 出度 | 既能按钮触发，也能收到数据自动打开 |
| `standalone` | 无入度、无出度 | 仅由按钮触发 |

生成的页面会自动：
- 为 `source` / `both` / `standalone` 弹窗生成**触发按钮**（按钮文字 = 第一个字段的 label）
- 为 `target` / `both` 弹窗生成**自动打开逻辑**（收到非空数据时 `setOpen(true)`）
- 保存成功后自动 `setOpen(false)` 关闭
- 使用 `destroyOnHidden`，关闭后销毁内容

### 3.2 弹窗里的表格

`Layout: "Modal"` + `Type: "Table"` 生成弹窗内的只读表格（`footer={null}`、宽 800），适合「查看详情」「列表选择」场景。

## 4. Container（容器）

通过嵌套结构组合多个组件，实现**模块化页面**：

```json
{
  "OrderPage": {
    "components": {
      "OrderSearch": { "Type": "Form", "Fields": [], "url": { "query": "/api/order/search" } },
      "OrderTable": { "Type": "Table", "Fields": [], "url": { "load": "/api/order/list" } }
    },
    "DataFlow": {
      "links": [
        { "from": "OrderSearch", "to": "OrderTable" }
      ]
    }
  }
}
```

### 4.1 特性

- **内联输出**：所有子组件生成在**同一个文件**里（`OrderPage.jsx`），不产生独立文件
- **任意嵌套**：容器里可以再放容器（见 [06](06-场景示例.md) 场景 6）
- **状态自动接线**：每个子组件自动获得 `XxxData` 状态，组件间通过 `value` / `setValue` 连接
- **边界透传**：`IN` / `OUT` 虚拟节点负责与外部交换数据

### 4.2 虚拟节点

| 节点 | 用法 | 效果 |
|------|------|------|
| `IN` | `{ "from": "IN", "to": "某子组件" }` | 外部传入的 `value` 变化 → 写入该子组件数据 |
| `OUT` | `{ "from": "某子组件", "to": "OUT" }` | 子组件数据 → `props.setValue` 输出到容器外部 |

```json
"DataFlow": {
  "links": [
    { "from": "IN", "to": "QuickSearch" },
    { "from": "QuickResult", "to": "OUT" }
  ]
}
```

## 5. 字段类型（Fields 详解）

所有控件类型：

| type | 生成控件 | 使用场景 |
|------|---------|---------|
| `Input`（默认） | 文本框 | 单行文本输入 |
| `Select` | 下拉框 | 单选 / 枚举选择 |
| `DatePicker` | 日期选择 | 日期输入（回显自动转 dayjs） |
| `InputNumber` | 数字输入 | 数值输入 |

### 5.1 Select 的两种选项来源

**静态选项**（写死在配置里）：

```json
{ "name": "STATUS", "type": "Select", "label": "状态",
  "options": [ { "value": "1", "label": "启用" }, { "value": "0", "label": "停用" } ] }
```

**动态字典**（运行时从后端加载，见 [05](05-集成配置.md)）：

```json
{ "name": "DEPT", "type": "Select", "label": "部门", "dictName": "SYS_DEPT" }
```

> `options` 和 `dictName` **二选一**。都写时以静态 `options` 为准。

### 5.2 通用属性

| 属性 | 说明 |
|------|------|
| `disabled` | `true` 时控件禁用（如编辑弹窗里的主键） |
| `rules` | antd 校验规则，原样进入配置（如 `[{ "required": true, "message": "请填写" }]`） |
