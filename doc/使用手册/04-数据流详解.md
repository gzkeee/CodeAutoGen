# 04 · 数据流详解

数据流（`DataFlow`）是本工具**最核心的能力**：用一条 `link` 声明「组件 A 的数据要传给组件 B」，
工具自动推导出**该做什么、触发什么事件、传什么数据**，生成对应的接线代码。

---

## 1. 基本语法

```json
"DataFlow": {
  "links": [
    { "from": "源组件", "to": "目标组件" }
  ]
}
```

`from` / `to` 引用**当前层级**的组件名。一条 link 就足够触发一次数据联动。

---

## 2. 行为自动推导

工具根据「源类型 → 目标类型」推导出行为标识，并据此生成代码：

| 源 → 目标 | 行为 | 触发事件 | 代码效果 |
|-----------|------|---------|---------|
| Form → Table | `formToTable` | 表单提交 `onFinish` | 查询结果 → 目标表格 dataSource |
| Table → Form | `tableToForm` | 表格行点击 `onRow` | 行数据 → 目标表单回显 `setFieldsValue` |
| Table → Table | `tableToTable` | 表格行点击 `onRow` | 行数据 → 目标表格用 `url.load` 重新加载明细 |
| Form → Form | `formToForm` | 表单值变化 `onValuesChange` | Select 变化 → 联动刷新目标表单 |
| Form → Container | `formToContainer` | 表单提交 `onFinish` | 提交数据 → 透传给容器 IN |
| Table → Container | `tableToContainer` | 表格行点击 `onRow` | 行数据 → 透传给容器 IN |
| Container → Form | `containerToForm` | 容器数据变化 | 容器数据 → 表单回显 |
| Container → Table | `containerToTable` | 容器数据变化 | 容器数据 → 表格展示 |
| Container → Container | `containerToContainer` | 容器数据变化 | 通过 IN/OUT 逐层透传 |
| 任意 → OUT | `toOut` | 视源类型 | 数据输出到页面级变量（父级 `setValue`） |

### 不支持的类型组合

`Form ↔ Form`、`Table → Form` 等都已覆盖；如果出现未定义组合（如 `Form → 无类型组件`），
解析器会抛出 `不支持的流向` 错误。

---

## 3. 各行为详解

### 3.1 Form → Table：查询后刷新表格（最常用）

```json
{ "from": "SearchForm", "to": "UserTable" }
```

生成的代码链路：

```jsx
// SearchForm 中
const res = await request.post('/api/user/list', values);
props.setValue(res['LIST'] || []);

// 页面容器自动接线
<SearchForm setValue={setUserTableData} />
<UserTable value={UserTableData} />
```

### 3.2 Table → Form：点击行 → 编辑弹窗回显

```json
{ "from": "UserTable", "to": "EditUserModal" }
```

生成效果：点击表格行 → 目标弹窗收到数据 → **自动打开**并 `setFieldsValue` 回显。

```jsx
// UserTable 中
const handleRowClick = (record) => {
  setValueEditUserModal(record);   // 把整行数据传过去
};

// EditUserModal（target 角色）自动打开 + 回显
useEffect(() => {
  if (props.value && 非空) setEditUserModalOpen(true);
}, [props.value]);
```

### 3.3 Table → Table：主从表（点击主表 → 加载明细）

```json
{ "from": "OrderTable", "to": "OrderDetailTable" }
```

点击主表行 → 明细表用 `url.load` 重新请求（把上游行作为参数传入）。

```jsx
useEffect(() => {
  const loadByValue = async () => {
    if (props.value && 非空) {
      const res = await request.get('/api/order/detail', /* 上游行数据 */);
      setDataSource(res['LIST'] || []);
    }
  };
  loadByValue();
}, [props.value]);
```

### 3.4 Form → Form：级联联动（省市区）

```json
{ "from": "ProvinceForm", "to": "CityForm" }
```

**约束**：源 Form 必须包含一个 `type: "Select"` 字段（工具用它的变化触发联动）。

生成效果：源表单的 Select 变化（`onValuesChange`）→ 目标表单收到选中值 → 重新加载。

### 3.5 容器相关（IN / OUT 透传）

容器边界上使用虚拟节点，与内部子组件连接：

```json
"links": [
  { "from": "IN",             "to": "QuickSearch" },   // 外部数据进容器
  { "from": "QuickSearch",    "to": "QuickResult" },
  { "from": "QuickResult",    "to": "OUT" }            // 容器数据出容器
]
```

- 容器之间的连接（`containerToContainer`）靠**逐层 IN/OUT** 完成数据透传
- 顶层组件也可以直接 `to: "OUT"`，把选中数据输出给页面的父级

---

## 4. 多出度：数据同时发给多个目标

一个组件可以有多条出站链接，工具会为每个目标自动区分 prop 别名：

```json
"links": [
  { "from": "ProvinceForm", "to": "CityForm" },
  { "from": "ProvinceForm", "to": "ResultTable" }
]
```

单出度时 prop 叫 `setValue`；多出度时自动改为 `set{目标名}`（如 `setCityForm`、`setResultTable`），互不干扰。
