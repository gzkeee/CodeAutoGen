# 07 · 生成代码与常见问题

---

## 1. 生成产物的目录结构

每次运行生成如下结构：

```text
<输出目录>/
├── index.jsx                          # 页面入口，组装所有顶层组件
└── components/
    ├── <顶层组件名>.jsx                # 每个顶层组件一个文件
    └── ...
```

- **顶层组件**（Form / Table / Modal / Container）各生成一个独立文件
- **Container 的子组件**内联进容器文件，不产生额外文件
- 文件经 **Prettier** 自动格式化

### 顶层页面组装（index.jsx）

```jsx
import React, { useState } from 'react';
import UserQueryForm from './components/UserQueryForm';
import UserResultTable from './components/UserResultTable';

const UserQueryPage = () => {
  const [UserQueryFormData, setUserQueryFormData] = useState({});
  const [UserResultTableData, setUserResultTableData] = useState([]);

  return (
    <div style={{ padding: '24px' }}>
      <UserQueryForm value={UserQueryFormData} setValue={setUserResultTableData} />
      <UserResultTable value={UserResultTableData} />
    </div>
  );
};
export default UserQueryPage;
```

## 2. 生成代码的特点

| 特性 | 说明 |
|------|------|
| **表单项配置化** | 字段元信息集中在组件内 `formItems` 常量（键值对，key=字段名），控件 JSX 通过 `{...formItems.KEY}` 展开 |
| **稳定的行 key** | 基于 WeakMap 生成器，相同记录返回相同 ID，避免重渲染问题 |
| **Modal 状态自动管理** | 打开/关闭、保存后自动关闭、`destroyOnHidden` |
| **目标弹窗自动打开** | `target`/`both` 弹窗收到数据时自动弹出 |
| **日期回显** | `DatePicker` 字段回显时自动 `dayjs()` 转换 |
| **错误与空态处理** | 请求失败提示 message，空数据正常渲染 |

## 3. 如何维护生成代码

生成代码是**可再生的**：重新运行生成命令会覆盖产物。因此正确姿势是 **改配置，而不是改 JSX**。

### 3.1 修改字段（改配置一处即可）

例如给查询表单加「邮箱」条件：

```json
// 配置里加一行
{ "name": "EMAIL", "type": "Input", "label": "邮箱" }
```

重新生成后，表单、请求参数、`formItems` 全部自动更新。

### 3.2 表单里手改字段标签 / 选项

生成的 `formItems` 是**键值对配置**，直接改这里即可（改完不会被生成器抹掉的风险
仅在你手动改配置源文件后重新生成才存在 —— 请始终改配置源）：

```jsx
const formItems = {
  USER_NAME: {
    name: 'USER_NAME',
    label: '用户名',            // ← 改这里，界面即时变化
    placeholder: '请输入用户名',
  },
  STATUS: {
    name: 'STATUS',
    label: '状态',
    options: [
      { value: '1', label: '启用' },   // ← 改选项也在这里
      { value: '0', label: '停用' },
    ],
  },
};
```

> 约定：**配置源是唯一真相**。需要持久化的修改请落在 JSON 配置，而不是生成产物里。

### 3.3 需要手写的部分

生成代码依赖目标工程的运行时模块，这些不在生成范围内：

- `@/utils/request`（HTTP 客户端）
- `@/utils/DataDict`（字典加载）
- `App.jsx` 挂载、路由、样式入口

## 4. 常见问题（FAQ）

### Q1. 生成的页面报 `Failed to resolve import "@/utils/request"`

目标工程缺少 `request` 模块或未配置 `@` 别名。

**解决**：
1. 在 `src/utils/` 下创建 `request.js`（开发期可用 Mock，见 [01](01-快速上手.md)）
2. 在 `vite.config.js` 配置别名 `'@'` → `path.resolve(__dirname, 'src')`

### Q2. 查询后表格没数据

- 检查 `request` 返回结构是否包含列表字段，默认从 `res.LIST` 取（`listField` 可配置）
- 检查后端返回的字段名与 `Fields` 的 `name` 是否一致

### Q3. 弹窗没有自动打开

确认该弹窗的**角色**推导正确：
- 要「点行自动弹出」→ 必须有入度（`Table → Modal` 的 link）
- 没有入度的弹窗是 `source`/`standalone`，只由按钮触发

### Q4. 下拉选项没加载出来

- 动态字典（`dictName`）需要目标工程提供 `@/utils/DataDict.getDict`，且返回 `[{ label, value }]`
- 返回字段不是 `label`/`value` 时，在 `src/config/dict.js` 配置 `labelField`/`valueField`
- 检查浏览器的网络面板，字典接口是否报错

### Q5. 按钮文字显示成「查 询」

这是 **antd 的自动行为**（在汉字间自动加空格以保证样式），不是生成 bug。修改成英文或加空格不影响功能。

### Q6. 新增/编辑 Modal 的标题

Modal 标题取**第一个字段的 label**。要改标题，调整该字段在 `Fields` 中的顺序或改其 `label`。

### Q7. 如何让多个组件的数据都流向同一个目标？

一个目标可以有多条入站 link（如 `AddUserModal → UserTable` 与 `EditUserModal → UserTable` 同时存在），
工具会为每个出度分配独立的 `setValue` 别名，互不干扰。

### Q8. 生成时报「组件 X 缺少有效的 Type 字段」

该组件既不是 `Type: "Form"/"Table"`，也没有嵌套 `components` + `DataFlow`（无法识别为容器）。
补上 `Type` 或嵌套结构即可。

### Q9. 如何把生成页面接入路由？

把 `index.jsx` 的默认导出组件接进路由即可：

```jsx
import UserQueryPage from '@/pages/UserQuery';
<Route path="/user-query" element={<UserQueryPage />} />
```

### Q10. 生成的代码能直接上生产吗？

能。生成代码就是标准 React 组件；但**开发验证流程**（Mock）需要在接入真实后端后替换 `@/utils/request`。
建议把生成目录纳入 CI：配置变更 → 重新生成 → 构建 → 发布。
