## 2. 项目概述

- **项目名称**：银行管理系统前端代码生成器
- **应用场景**：针对银行后台管理系统中高频使用的**数据查询、展示、保存、联动**场景，通过解析标准化 JSON 配置文件，自动生成可直接运行的 React + Ant Design 代码。
- **核心目标**：消除重复性的 CRUD 代码编写，确保代码风格统一，提升开发效率 80% 以上。
- **输出语言**：纯 JavaScript（.jsx / .js），无 TypeScript 依赖。


## 3. 核心设计哲学

### 3.1 配置即代码（Configuration as Code）
开发者无需编写 React JSX，只需维护简洁的 JSON Schema 配置文件。

### 3.2 约定优于配置（Convention over Configuration）
通过组件类型自动推导数据流向行为，无需额外配置 `trigger` 或 `dataPass` 字段。

### 3.3 树状组件结构（Tree-structured Components）
组件可以嵌套子组件，形成树状层级。每个复合组件（Container）拥有独立的 `components` 和 `DataFlow`，实现功能封装与复用。

### 3.4 数据流驱动（Data Flow Driven）
页面逻辑通过 `links` 数组定义数据流向（`from` → `to`），生成器自动推导触发时机、数据截取和目标行为。

- `IN`：表示组件从外部（父级或兄弟组件）接收数据
- `OUT`：表示组件向外部（父级或兄弟组件）输出数据

### 3.5 布局驱动（Layout Driven）
通过 `Layout` 字段控制组件的展示形式。目前支持 `Modal` 弹窗模式，未来可扩展 `Drawer`、`Card` 等布局形式。

### 3.6 组件函数式接口
所有组件遵循统一的函数式接口规范：

```javascript
// 组件 Props 约定
// value: 外部传入的数据（初始化、筛选条件、展示数据）
// setValue: 将内部产生的数据回传给父级
// visible: Modal 的显示状态（仅 Layout: "Modal" 时存在）
// setVisible: 控制 Modal 显示/隐藏（仅 Layout: "Modal" 时存在）
// 示例：{ value: {}, setValue: (val) => void, visible: false, setVisible: (bool) => void }
```

### 3.7 API 内联原则
所有 API 请求（`load` / `query` / `save`）直接写在组件内部，不生成独立的 service 文件。

### 3.8 文件组织原则（V7.1 确立）

| 原则 | 说明 |
| :--- | :--- |
| **一文件对应一复合组件** | 每个 Container 生成一个 `.jsx` 文件，所有子组件（Form/Table）合并到该文件中 |
| **扁平输出** | 所有组件文件直接放在 `components/` 目录下，不创建子文件夹 |
| **叶子组件不独立成文件** | Form/Table 作为复合组件的内部组成部分，不单独生成文件 |
| **根页面为 `index.jsx`** | 页面入口文件，位于页面根目录 |

> **设计理由**：
> - 每个复合组件只有一个文件，无需文件夹包裹，避免冗余层级
> - 减少文件数量，降低项目的认知负担
> - 叶子组件与容器紧密耦合，放在同一文件中更易于理解和维护
> - 导入路径简洁：`import ComponentA from './components/ComponentA'`


## 4. 配置文件规范（输入 Schema）

### 4.1 顶层结构

```json
{
  "components": {
    "ComponentA": { ... },    // 复合组件（Container）
    "ComponentB": { ... },    // 复合组件（Container）
    "GlobalSearchForm": { "Type": "Form", ... }  // 顶层独立组件（可选）
  },
  "DataFlow": {
    "links": [
      { "from": "ComponentA", "to": "ComponentB" },
      { "from": "GlobalSearchForm", "to": "ComponentA" }
    ]
  }
}
```

### 4.2 复合组件（Container）结构

每个复合组件是一个独立的**功能单元**，包含：
- 自己的子组件列表（`components`）
- 自己的数据流定义（`DataFlow`）
- 可选的 `IN` / `OUT` 虚拟节点，用于与外部通信

```json
{
  "ComponentA": {
    "components": {
      "SearchForm": {
        "Type": "Form",
        "Fields": [
          { "name": "PROCESS_ID", "type": "Input", "label": "流程号" },
          {
            "name": "PROCESS_STATUS",
            "type": "Select",
            "label": "流程状态",
            "options": [
              { "value": "1", "label": "待处理" },
              { "value": "2", "label": "处理中" },
              { "value": "3", "label": "处理完成" }
            ]
          }
        ],
        "url": {
          "load": "/api/dict/status",
          "query": "/api/process/query"
        }
      },
      "ResultTable": {
        "Type": "Table",
        "Fields": [
          { "name": "PROCESS_ID", "label": "流程号" },
          { "name": "PROCESS_STATUS", "label": "流程状态" },
          { "name": "TASK_ID", "label": "任务编号" }
        ],
        "url": {
          "save": "/api/process/update"
        }
      },
      "AddForm": {
        "Type": "Form",
        "Layout": "Modal",
        "Fields": [
          { "name": "NAME", "type": "Input", "label": "名称" }
        ],
        "url": {
          "save": "/api/process/add"
        }
      }
    },
    "DataFlow": {
      "links": [
        { "from": "SearchForm", "to": "ResultTable" },
        { "from": "AddForm", "to": "ResultTable" },
        { "from": "ResultTable", "to": "OUT" }
      ]
    }
  }
}
```

### 4.3 虚拟节点：IN 和 OUT

`IN` 和 `OUT` 是特殊的虚拟节点，用于描述组件与外部世界的数据交互：

| 虚拟节点 | 含义 | 使用场景 |
| :--- | :--- | :--- |
| **`IN`** | 组件需要从外部接收数据 | 作为 `links` 的 `to` 目标，表示该组件的数据源来自外部 |
| **`OUT`** | 组件要向外部输出数据 | 作为 `links` 的 `from` 源，表示该组件产生的数据需要传递给外部 |

**示例**：
```json
// ComponentA 将 ResultTable 的数据输出到外部
{ "from": "ResultTable", "to": "OUT" }

// ComponentB 从外部接收数据作为输入
{ "from": "IN", "to": "TaskSearchForm" }
```

### 4.4 顶层混合节点支持

顶层 `components` 对象中允许**同时声明 Container、Form、Table 三种类型**，顶层 `DataFlow.links` 支持**任意类型之间的自由连接**。

| 连接类型 | 说明 |
| :--- | :--- |
| **Container → Container** | 复合组件之间数据传递 |
| **Container → Form/Table** | 复合组件输出到独立组件 |
| **Form/Table → Container** | 独立组件输入到复合组件 |
| **Form/Table → Form/Table** | 独立组件之间直接连接 |


## 5. Layout 字段详解（Modal 模式）

### 5.1 字段定义

在组件定义中新增 `Layout` 字段，用于指定组件的展示形式：

```json
{
  "AddForm": {
    "Type": "Form",
    "Layout": "Modal",   // 可选值：'Modal'，不配置则默认直接渲染在页面中
    "Fields": [...],
    "url": { "save": "/api/add" }
  }
}
```

### 5.2 支持的值

| 值 | 含义 | 说明 |
| :--- | :--- | :--- |
| 不配置 | 普通模式 | 组件直接渲染在页面主体中 |
| `"Modal"` | 弹窗模式 | 组件以 Ant Design Modal 弹窗形式呈现 |

### 5.3 Modal 行为规则

| 角色 | 行为描述 | 触发方式 | 关闭方式 |
| :--- | :--- | :--- | :--- |
| **作为源组件（From）** | 弹窗由目标组件中的按钮触发打开，操作完成后将数据传给目标组件，弹窗自动关闭 | 目标组件自动生成触发按钮 | 数据传输完成后自动关闭 |
| **作为目标组件（To）** | 弹窗在源组件传输数据后自动打开，用于展示或回显数据 | 源组件触发数据传递时自动打开 | 用户手动关闭 |

### 5.4 Modal 嵌套支持

**Modal 支持嵌套**，即一个 Modal 组件内部可以触发打开另一个 Modal 组件。

| 嵌套场景 | 是否支持 |
| :--- | :--- |
| 普通组件 → Modal | ✅ 支持 |
| Modal 内 → 另一个 Modal | ✅ 支持 |
| 多层 Modal 嵌套 | ✅ 支持（建议不超过 3 层） |
| 同一 Modal 自嵌套 | ❌ 不支持 |


## 6. 数据流向自动推导规则

### 6.1 四种基础流向

| 流向 (From → To) | 自动绑定的触发时机 | 自动传递的数据内容 | 目标组件接收后的默认行为 |
| :--- | :--- | :--- | :--- |
| **Form → Table** | Form 的 `onFinish`（点击查询/重置） | 接口响应的 **`res.LIST`** | 直接作为 Table 的 `dataSource` 渲染 |
| **Table → Form** | Table 的 `onRowClick`（点击行） | 被点击的**整行对象 `record`** | 触发表单的 `form.setFieldsValue(record)` 回显 |
| **Table → Table** | Table 的 `onRowClick`（点击主行） | 被点击的**整行对象 `record`** | 提取 `record.id`，触发子 Table 的 `load` 请求加载明细 |
| **Form → Form** | 源 Form 中第一个 `type="Select"` 的 `onChange` | 下拉框选中的 **`value`** | 触发目标 Form 的 `load` 请求，加载级联下拉选项 |

### 6.2 虚拟节点规则

| 流向 | 处理逻辑 |
| :--- | :--- |
| **`{ from: "组件", to: "OUT" }`** | 该组件产生的数据通过 `props.setValue` 传递给父级容器 |
| **`{ from: "IN", to: "组件" }`** | 该组件接收的 `value` 数据来自父级容器 |

### 6.3 顶层混合连接规则

| 连接类型 | 处理逻辑 |
| :--- | :--- |
| **Container → Container** | 源 Container 的 OUT 数据 → 目标 Container 的 IN |
| **Container → Form/Table** | 源 Container 的 OUT 数据 → 目标组件的 `value` 属性 |
| **Form/Table → Container** | 源组件的 `setValue` → 目标 Container 的 IN |
| **Form/Table → Form/Table** | 源组件的 `setValue` → 目标组件的 `value` 属性 |


## 7. 输出规范（生成的代码文件）

### 7.1 文件结构（V7.1 扁平结构）

```
/src/pages/{PageName}/
├── index.jsx                      # 根页面入口
└── components/
    ├── ComponentA.jsx             # 复合组件 A（含 SearchForm + ResultTable + AddForm）
    ├── ComponentB.jsx             # 复合组件 B（含 TaskSearchForm + TaskResultTable）
    ├── GlobalSearchForm.jsx       # 顶层独立 Form（如存在）
    └── DetailTable.jsx            # 顶层独立 Table（Modal 模式，如存在）
```

### 7.2 复合组件文件内部结构

```jsx

import { Form, Input, Select, Button, Table, Modal, message } from 'antd';
import request from '@/utils/request';

// ============================================================
// 子组件 1：SearchForm（查询表单）
// ============================================================
const SearchForm = (props) => { ... };

// ============================================================
// 子组件 2：ResultTable（数据表格）
// ============================================================
const ResultTable = (props) => { ... };

// ============================================================
// 子组件 3：AddForm（新增弹窗 - Modal 模式）
// ============================================================
const AddForm = (props) => { ... };

// ============================================================
// 复合组件 Container：ComponentA
// ============================================================
const ComponentA = (props) => {
  // 内部状态管理
  const [tableData, setTableData] = useState([]);
  const [outputData, setOutputData] = useState(null);

      props.setValue(outputData);
```

## 9. 生成器核心实现逻辑

### 9.1 处理流程

1. **解析层（Parser）**：读取并校验 JSON 配置，递归解析树状结构，识别 Container、Form、Table 及 Layout 配置
2. **模型层（Model Builder）**：构建组件拓扑图，计算入度/出度，识别 IN/OUT 虚拟节点，推导 Modal 行为角色
3. **规则引擎（Rule Engine）**：遍历 `links`，根据源/目标类型自动推导触发时机、数据截取和目标行为
4. **渲染层（Renderer）**：使用模板字符串拼接代码，将同一 Container 下的所有子组件合并到同一文件
5. **优化层（Optimizer）**：调用 Prettier 对生成的代码进行自动格式化
6. **输出层（Writer）**：将文件写入目标工程目录（扁平结构，不创建子文件夹）

### 9.2 核心映射逻辑

```javascript
function getBehavior(fromType, toType) {
  if (fromType === 'Form' && toType === 'Table') return 'formToTable';
  if (fromType === 'Table' && toType === 'Form') return 'tableToForm';
  if (fromType === 'Table' && toType === 'Table') return 'tableToTable';
  if (fromType === 'Form' && toType === 'Form') return 'formToForm';
}

function resolveModalBehavior(comp, link) {
  if (!comp.layout || comp.layout !== 'Modal') return null;
  
  const isFrom = link.from === comp.id;
  const isTo = link.to === comp.id;
  
  if (isFrom) {
    return { role: 'source', autoClose: true };
  }
  if (isTo) {
    return { role: 'target', autoClose: false };
  }
  return null;
}
```

## 12. 核心设计决策总结

| 决策点 | 结论 |
| :--- | :--- |
| 配置文件格式 | JSON（树状结构，支持嵌套） |
| 组件类型 | Form / Table / Container |
| 数据流向 | DataFlow.links 声明，自动推导触发时机和行为 |
| 虚拟节点 | IN / OUT（跨层级数据传递） |

## 13. 请求层自定义（V8.0）

### 13.1 背景

不同项目的 HTTP 请求封装各不相同。有的使用 `request.get/post`，有的使用 `axios`，有的使用内部封装的 `api.post`。V7.1 及之前版本硬编码为 `request.get/post` 风格，无法适配不同项目。

### 13.2 设计目标

- 移除对 `request` 的硬编码依赖
- 通过配置文件 `src/config/request.js` 自定义 import 语句和调用模板
- 保持向后兼容，不修改原有配置即可生成与 V7.1 完全相同的代码

### 13.3 配置结构

配置文件路径：`src/config/request.js`

```js
const requestConfig = {
  // import 语句模板
  importStatement: "import request from '@/utils/request';",

  // 请求方法调用模板
  methods: {
    load:  "request.get('{{url}}', {{config}})",    // url.load → 初始化加载
    query: "request.post('{{url}}', {{data}})",     // url.query → 查询提交
    save:  "request.post('{{url}}', {{data}})",     // url.save  → 保存提交
  },

  // 列表中数据所在的响应字段路径
  listField: 'LIST',
};
```

### 13.4 模板变量

| 变量 | 说明 | 使用场景 |
|:---|:---|:---|
| `{{url}}` | API 地址（需模板自行加引号） | load / query / save |
| `{{data}}` | 请求体变量名，默认 `values` | query / save |
| `{{config}}` | 配置参数变量名，默认 `undefined` | load |

### 13.5 methods 的 key 说明

| Key | 对应 url 字段 | 语义 | 传参 |
|:---|:---|:---|:---|
| `load` | `url.load` | 组件挂载时初始化加载 | `{{config}}`（配置参数） |
| `query` | `url.query` | 查询/搜索提交 | `{{data}}`（表单数据） |
| `save` | `url.save` | 新增/编辑保存 | `{{data}}`（表单数据） |

### 13.6 常见适配示例

#### 1. 全 POST 项目（用户场景）

```js
const requestConfig = {
  importStatement: "import api from '@/utils/api';",
  methods: {
    load:  "api.post('{{url}}', {{config}})",
    query: "api.post('{{url}}', {{data}})",
    save:  "api.post('{{url}}', {{data}})",
  },
  listField: 'data.records',
};
```

#### 2. axios 混用 GET/POST

```js
const requestConfig = {
  importStatement: "import axios from 'axios';",
  methods: {
    load:  "axios.get('{{url}}', { params: {{config}} })",
    query: "axios.get('{{url}}', { params: {{data}} })",
    save:  "axios.post('{{url}}', {{data}})",
  },
  listField: 'data.list',
};
```

### 13.7 默认配置

默认配置定义在 `src/config/defaults.js` 的 `request` 段中。用户配置通过 `src/config/request.js` 覆盖，采用浅合并（methods 内层也是逐 key 覆盖）。


## 14. 数据字典（Select 动态选项，V8.0）

### 14.1 背景

在实际业务系统中，Select 下拉选项经常从后端字典接口动态获取，而不是硬编码在 JSON 配置中。V7.1 及之前只支持内联 `options` 数组，每次都需要写完整的 `{value, label}` 列表，重复且难以维护。

### 14.2 设计目标

- 支持字段级 `dictName` 配置，自动生成异步字典加载代码
- 字典调用方式可配置，适配不同项目的字典服务封装
- 内联 `options` 与动态 `dictName` 可混用，互不干扰
- 支持自定义响应字段映射（labelField / valueField）

### 14.3 字段配置

在 Select 字段中指定 `dictName` 即可启用动态字典加载，**不需要**再写 `options`：

```json
{
  "name": "DEPT",
  "type": "Select",
  "label": "部门",
  "dictName": "SYS_DEPT"
}
```

### 14.4 生成的代码

```jsx
const [DEPT_options, setDEPT_options] = useState([]);

useEffect(() => {
  const loadDict = async () => {
    const res = await DataDict.getDict('SYS_DEPT');
    setDEPT_options(res || []);
  };
  loadDict();
}, []);

// JSX
<Select placeholder="请选择部门" options={DEPT_options} />
```

### 14.5 混合使用

字典字段和静态 options 可以共存：

```json
{
  "Fields": [
    { "name": "DEPT",  "type": "Select", "label": "部门", "dictName": "SYS_DEPT" },
    { "name": "STATUS", "type": "Select", "label": "状态", "options": [
      { "value": "1", "label": "启用" },
      { "value": "0", "label": "停用" }
    ]}
  ]
}
```

字典字段生成动态 `useEffect` 加载，静态字段渲染 `Select.Option` 子元素。

### 14.6 配置结构

配置文件路径：`src/config/dict.js`

```js
const dictConfig = {
  // import 语句模板
  importStatement: "import DataDict from '@/utils/DataDict';",

  // 调用表达式模板，{{dictName}} 替换为字段配置的 dictName
  method: "DataDict.getDict('{{dictName}}')",

  // 返回值中用作展示 label 的字段名（默认 label）
  labelField: 'label',

  // 返回值中用作实际 value 的字段名（默认 value）
  valueField: 'value',
};
```

### 14.7 字段映射说明

如果后端字典接口返回字段名不是 `label`/`value`（例如返回 `{ text: '启用', id: '1' }`），工具会在生成的代码中自动添加 map 转换：

| labelField | valueField | 生成的代码 |
|:---|:---|:---|
| `label`（默认） | `value`（默认） | `setOptions(res \|\| [])` |
| `text` | `id` | `setOptions((res \|\| []).map(item => ({ label: item['text'], value: item['id'] })))` |

### 14.8 默认配置

默认配置定义在 `src/config/defaults.js` 的 `dict` 段：

```js
dict: {
  importStatement: "import DataDict from '@/utils/DataDict';",
  method: "DataDict.getDict('{{dictName}}')",
  labelField: 'label',
  valueField: 'value',
}
```

用户通过 `src/config/dict.js` 逐 key 覆盖。
